Below is a realistic architecture similar to tools like Salesforce Inspector and Salesforce Advanced Inspector, and conceptually comparable to FuseKit.
This is how a professional Salesforce Chrome extension should be architected if you want it to scale and support multiple orgs, metadata exploration, SOQL generation, and AI tools.

1. High-Level Architecture
Browser (Chrome / Edge)
        │
        │
Chrome Extension
 ├── Popup UI
 ├── Background Service Worker
 ├── Content Scripts
 ├── Local Storage Layer
 └── API Layer
        │
        │
Salesforce Platform
 ├── REST API
 ├── Tooling API
 ├── Metadata API
 └── OAuth Server

The extension runs entirely in the browser, similar to Salesforce Inspector, and communicates directly with Salesforce APIs.

3. Authentication Architecture

Uses Salesforce OAuth 2.0.

Flow:

User clicks Login
      │
Redirect to Salesforce OAuth
      │
User approves access
      │
Salesforce returns access token
      │
Extension stores token

Endpoints:

/services/oauth2/authorize
/services/oauth2/token

Token storage:

chrome.storage.local

Org session format:

{
  orgId,
  instanceUrl,
  accessToken,
  refreshToken,
  userName
}

5. Metadata Engine

This is the core engine powering SOQL generation.

It loads and caches metadata.

metadata-engine/
 ├ object-index.ts
 ├ field-index.ts
 ├ relationship-engine.ts

Metadata structure stored locally:

Object
 ├ fields
 ├ parentRelationships
 └ childRelationships

Example:

Account
 ├ fields
 │   ├ Name
 │   ├ Industry
 │   └ OwnerId
 └ childRelationships
     ├ Contacts
     └ Opportunities
6. Relationship Engine

Responsible for building correct SOQL relationships.

Parent → Child
Account → Contacts

Generated query:

SELECT Id,
 (SELECT Id, LastName FROM Contacts)
FROM Account
Child → Parent
Contact → Account

Generated query:

SELECT Id, Account.Name
FROM Contact

Algorithm:

1 Load object metadata
2 Parse childRelationships
3 Parse reference fields
4 Build relationship tree
